# note 論文リライター

note の記事を、ブラウザに組み込まれた LLM で、論文のように読みやすい構成に書き換える拡張機能です。書き換えは端末の中だけで行います。記事の本文が外部に送られることはなく、料金もかかりません。

> **状態：試作で止めています。** Chrome で動くことは確かめました。ただ、試した Mac（Intel、GPU なし相当）では書き換えにかなり時間がかかり、実用には向きませんでした。詳しくは「[試した結果](#試した結果)」を見てください。

## できること

note の記事のページを開くと、右下に「論文風に書き換える」ボタンが出ます。押すと、本文がまるごと次の構成に置き換わります。元の文章は残しません。

1. **タイトル**：内容に合わせて付け直したもの
2. **要約**：記事全体の目的・主張・結論を 3〜5 文で
3. **目次**：各節へのリンク
4. **本文**：節ごとに、見出しと段落が並びます

本文は、**パラグラフリーディング**（各段落の最初の文だけを拾い読みすること）で内容がわかるように書きます。各段落の最初の文でその段落の主張を言い切り、続く文はその理由・具体例・補足だけにします。

もう一度ボタンを押すと、元の記事と書き換えた記事を切り替えられます。

## 仕組み

ブラウザに組み込まれた LLM を、JavaScript から呼ぶ API（Prompt API、`LanguageModel`）を使っています。Edge では Phi-4-mini、Chrome では Gemini Nano というモデルが、端末の中で動きます。

内蔵のモデルは小さく、一度に読める長さに限りがあります。そのため、次の順に分けて書き換えます。

1. **本文を取り出す**：記事の本文（`#note-body`）の要素を順に読みます。note が自動で作る目次は除き、見出しには印を付けます。
2. **分ける**：モデルが一度に読める量（`inputQuota`）の約 4 分の 1 を目安に、本文を分けます。見出しの位置ではなるべく区切り、長すぎる段落は文の区切りで割ります。
3. **節ごとに書き換える**：分けた部分ごとに、「見出し 1 行と、空行で区切った 2〜5 個の段落」の形で書き換えさせます。前の節の会話で文脈が埋まらないよう、毎回、指示だけを与えた状態の会話を複製して使います（`session.clone()`）。
4. **タイトルと要約を作る**：各節の見出しと、各段落の最初の文だけをモデルに渡して、タイトルと要約を作らせます。パラグラフリーディングで読める本文になっていれば、最初の文だけで全体の要約が作れる、という考え方です。
5. **表示する**：タイトル、要約、目次、本文を組み立てて、元の本文と入れ替えます。モデルの出力は HTML として解釈せず、文字としてだけ入れます。

note はページを読み直さずに記事を移る作りなので、URL の変化を 1 秒ごとに見て、記事のページでだけボタンを出します。

### ファイル

| ファイル | 中身 |
|---|---|
| `manifest.json` | 拡張機能の設定（Manifest V3）。`https://note.com/*` でだけ動きます |
| `content.js` | 本文の取り出し、分割、モデルの呼び出し、表示まで、処理のすべて |
| `content.css` | ボタンと、論文風の見た目（明朝体、字下げ、要約の枠など） |

## 使える条件

ブラウザに組み込まれた LLM は、端末の性能の条件を満たさないと使えません。2026 年 11 月の時点の、公式ドキュメントに書かれた条件です。

### Chrome（Gemini Nano）

- **OS**：Windows 10 / 11、macOS 13 以降、Linux、ChromeOS（Chromebook Plus）
- **性能**：GPU のメモリが 4 GB より多い。または、メモリ 16 GB 以上で CPU 4 コア以上（CPU で動かす場合。Chrome 140 から）
- **ディスク**：Chrome のプロフィールがあるドライブに、22 GB 以上の空き
- **回線**：通信量の制限がない回線（最初のモデルのダウンロードのとき）
- **拡張機能から使えるか**：Chrome 138 以降の安定版で、フラグなしで使えます
- **日本語**：Chrome 149 以降で、入出力とも対応しています

### Edge（Phi-4-mini / Aion-1.0-Instruct）

- **OS**：Windows 10 / 11、macOS 13.3 以降
- **性能**：GPU のメモリ 5.5 GB 以上（Phi-4-mini の場合）
- **ディスク**：Edge のプロフィールがあるドライブに、20 GB 以上の空き
- **回線**：通信量の制限がない回線
- **チャネル**：ドキュメントでは Canary / Dev の 138 以降。`edge://flags` で「Prompt API for on-device language model」を有効にします
- **性能が足りない端末**：`edge://on-device-internals` の「Device performance class」が High 以上なら Phi-4-mini が使えます。Medium / Low の端末では、「Enable prerelease on-device language model」を有効にすると、CPU でも動く小さいモデル（Aion-1.0-Instruct、Edge 150 以降）が使えます。

## 入れ方

### Chrome

1. `chrome://extensions` を開く
2. 右上の「デベロッパー モード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」で、このフォルダを選ぶ

### Edge

1. `edge://flags` で「Prompt API for on-device language model」を Enabled にして、Edge を再起動する
2. `edge://extensions` を開き、「開発者モード」をオンにする
3. 「展開して読み込み」で、このフォルダを選ぶ

どちらも、`chrome://on-device-internals` / `edge://on-device-internals` で、端末の性能の区分とモデルの状態を確かめられます。最初にボタンを押したときに、モデル（数 GB）のダウンロードが始まります。

## 試した結果

GPU のメモリが少ない端末で、Edge と Chrome を試しました。

### Edge：動かなかった

- 「この端末では内蔵の LLM が使えません」と出ました。`LanguageModel.availability()` が `"unavailable"` を返したということです。
- `edge://on-device-internals` の「Device performance class」は **Very Low** でした。GPU のメモリが Phi-4-mini の条件（5.5 GB）に届いていませんでした。
- 「Enable prerelease on-device language model」を有効にして、CPU で動く Aion-1.0-Instruct に切り替えても、使えないままでした。ドキュメントで Aion の対象とされているのは Medium と Low だけで、Very Low は対象外のようです。

### Chrome：動いたが、遅すぎた

- CPU で動かす条件（メモリ 16 GB 以上、CPU 4 コア以上）を満たしていたので、拡張機能のコードは変えずに、そのまま動きました。
- ただ、CPU で動かすため、書き換えに時間がかかりすぎて、記事を読むための道具としては使えませんでした。

### わかったこと

- ブラウザ内蔵の LLM は、無料で、本文を外に出さずに使えるのが利点です。一方で、**動く端末を選びます**。同じ API でも、Edge と Chrome とで条件が違い、片方だけで動くことがあります。
- 記事の全文を書き換えるような、出力が長い作業を CPU で動かすのは厳しいです。GPU のメモリに余裕のある端末なら、もっと速く動く可能性があります（試していません）。
- 実用にするなら、次のどちらかに作り替えるのが現実的です。
  - **Mac で動かすモデル**（Ollama など）：本文は外に出ません。ただし、速さは端末の性能次第です。
  - **外部の API**（Gemini API など）：速くて文章の質も高いです。その代わり、記事の本文が外部に送られ、API キーが必要です。

## 制限

- 有料記事は、見えている部分だけが対象です。
- 画像、埋め込み、表は、書き換えたあとには残りません。
- 小さいモデルなので、言い回しが不自然になったり、元の記事にない内容が混ざったりすることがあります。
- 独自ドメインの note（note pro）には対応していません。
- エラーの文面は Edge 向けのままです（Chrome で使えない場合も、Edge のフラグの案内が出ます）。
